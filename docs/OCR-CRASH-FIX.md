# 인식 중 비정상 종료 수정 — 1.0.1 (2026-09-04)

## 확인한 증상과 근거

인게임 인식 하단에 `Another RecognizeAsync operation is already running!`이 표시되고
프로그램이 종료되는 현상을 조사했습니다.

Windows Application 이벤트 로그에서 같은 날 21:08:10, 21:09:38, 21:10:37의 충돌을 확인했습니다.
실행 후 경과 시간은 각각 약 44.5초, 62.7초, 24.6초로 일정하지 않았습니다.
정해진 인식 횟수나 시간이 되면 종료하는 로직이 아니라, 작업이 겹치거나 취소되는 시점의 오류입니다.
각 실행의 정확한 인식 횟수는 해당 Windows 이벤트만으로 알 수 없습니다.

충돌한 실행 파일은 기존 `github-upload/app/DnfItemChecker.App.exe`였습니다.
이벤트 1000의 예외 코드는 `0xc0000005`이고, 이벤트 1026의 스택은 다음 경로를 가리켰습니다.

```text
SkiaSharp.SkiaApi.sk_bitmap_get_info
RapidOcrNet.TextRecognizer.GetTextLine
OnnxOcrService.RecognizeLinesAsync / RecLane
```

## 원인과 수정

1. **ONNX 인식 중 이미지가 먼저 해제됨**
   - 기존 `Task.WaitAll(lanes, ct)`는 취소 시 다른 lane이 종료되기 전에 대기를 끝냈습니다.
   - `finally`가 crop 이미지를 해제하면 계속 실행 중인 lane이 해제된 native 메모리에 접근했습니다.
   - 모든 lane을 `Task.WhenAll`로 끝까지 기다린 뒤 이미지를 해제하도록 변경했습니다.
     취소는 다음 이미지 인식 전에 확인하고 이미 시작한 native 호출의 입력은 유지합니다.

2. **Windows OCR 엔진에 동시 요청**
   - 시작 시 warm-up, 즉시 인식, 정밀 보정이 동일한 `OcrEngine`을 공유했습니다.
   - 엔진별 비동기 gate로 한 번에 한 요청만 실행합니다. 대기 중 취소된 요청은 실행하지 않습니다.
   - WinRT 작업에 취소를 직접 전달해 자원을 일찍 반환하지 않고, 각 작업이 끝난 후 취소 결과를 반영합니다.

3. **종료 및 재시작 경합**
   - ONNX 모델 초기화·추론이 끝난 뒤 native 세션을 해제합니다.
   - 병렬 Windows/ONNX 단계는 한쪽에서 실패해도 다른 쪽의 완료를 확인합니다.
   - 탭/포커스 변경 후 이전 foreground 인식이 아직 정리 중이면 다음 tick은 새 인식을 시작하지 않습니다.

단순히 오류 메시지를 숨기거나 인식 횟수·실행 시간을 제한하지 않았습니다.
Windows OCR과 ONNX 간 병렬 처리, ONNX 내부 4개 lane은 유지했습니다.
안전한 취소를 위해 이미 시작된 native 호출 하나가 끝날 때까지 취소 반영이 지연될 수 있습니다.

## 검증

- 기존 134개 테스트와 새 native OCR 회귀 테스트 4개, 총 **138개 통과**.
- 동일 Windows OCR 엔진에 16개 요청을 겹쳐 보내고 일부 취소한 뒤 정상 재인식 확인.
- 실제 ONNX 모델로 32회 반복 취소 및 재시도, 마지막 전체 OCR 정상 인식 확인.
- 추론 중 Dispose 및 초기화 중 Dispose 후 재호출 차단 확인.
- 테스트 입력은 자체 생성한 텍스트 이미지이며 개인 캡처를 저장소에 추가하지 않았습니다.
- 기존 전체 데이터셋 재검증: 핵심 필드 **143/143**, 능력치 값 **176/176**, 실패 0건.
  평균 약 459ms / P95 약 548ms로 측정됐습니다. 1회 측정이며 속도 개선을 입증하는 비교 실험은 아닙니다.

이 검증은 재현된 native 자원 경합에 대한 검증입니다. 실제 게임 장시간 사용 검증은 사용 환경에서 추가 확인이 필요합니다.
